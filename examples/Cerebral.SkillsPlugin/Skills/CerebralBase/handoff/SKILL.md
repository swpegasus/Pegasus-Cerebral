# Hand off verified work

Capture the current objective, accepted requirements, exact workspace and task identity, source ownership, verified progress, unresolved conditions, and the next meaningful authorized action.

Link to maintained source, specifications and evidence rather than duplicating histories. Include the actual verification tier and omitted checks. Preserve operation and receipt identities when needed for recovery, including whether an outcome is accepted, working, terminal, uncertain or waiting on the owner.

Keep the human owner distinct from agents. Preserve holds and explicit permission boundaries. A handoff is reference material; it does not grant the receiving agent new tools, file roots, services, model work, deployment or replay authority.

Use Cerebral's existing authorized continuity or handoff route with the correct task and project binding. Do not fabricate another task's cache, copy raw transcripts, or persist private reasoning, credentials, hidden messages or unrelated personal data. Create a separate file or send a message only when that action is authorized.

End with enough bounded public context for a qualified engineer to continue without guessing which claims were merely planned. Do not mark unfinished work complete.
